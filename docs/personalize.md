# 搭建属于你的科研助手

先选一个你每天都要处理的任务，接入自己的资料和工具，再逐步扩展。研究方向可以是水文、计算机、材料或其他学科；具体工具和数据由使用者选择。

本页说明如何组织个人接入。完整容器部署的环境和依赖见 [快速开始](setup.md)，现有服务与路径见 [架构](architecture.md)。

## 1. 选一个任务作为起点

| 起点 | 准备的资源 | 第一次可检查的结果 |
|---|---|---|
| 文献整理 | 自己的一组论文、文献库或资料目录 | 一份附来源的阅读笔记和待阅读清单 |
| 科研编程 | 一个已有代码仓库、运行说明和测试命令 | 修改内容、实际命令、测试结果与日志位置 |
| 日常秘书 | 自己的待办、会议记录或关注的信息源 | 一份可执行的行动清单或每日简报 |

先确定结果保存在哪里、怎样判断完成。涉及代码与实验时，沿用课题自己的环境、数据划分、运行命令和评价标准。

## 2. 登记自己的资源

| 资源 | 需要明确的内容 | 接入位置 |
|---|---|---|
| 模型与 Agent | 使用哪个执行工具、模型端点和凭据，谁负责阅读或编码 | 所选 Agent 的配置；完整主栈使用 `.env` 和配置模板 |
| 项目与数据 | 代码仓库、资料目录、计算环境、输入和输出位置 | 本地文件、Git、容器挂载、已有项目命令 |
| 文献与笔记 | 文献库 ID、附件路径、个人知识库、笔记保存位置 | [Zotero](zotero-cli-cc.md)、[语雀](yuque-mcp-hermes.md)、文件工具 |
| 对话与通知 | 自己的终端、飞书应用或 Discord 频道，通知发给谁 | [Hermes](hermes-channels.md)、[OpenClaw](openclaw-channels.md)、[飞书 CLI](lark-cli.md) |
| 日常事务 | 待办类型、邮箱、信息源与提醒时间 | [aisecretary](aisecretary.md)、[邮件](email.md)、[dailyinfo](dailyinfo.md) |

可以把任务约定写进所选 Agent 的项目说明。下面是一份自然语言任务示例，**不是本仓库自动读取的配置格式**：

```text
任务：整理我的课题仓库本周进展，列出下一步工作。
输入：我指定的 Git 仓库、运行日志目录与本周笔记。
过程：读取提交和日志；必要时运行项目文档中已有的检查命令。
输出：写入我指定的笔记目录，关联提交、命令与结果位置。
验收：每条进展有依据，失败任务保留原因，待办可直接执行。
```

## 3. 选择自己的使用入口

| 方式 | 怎么开始 |
|---|---|
| 已经使用 Agent 或编码助手 | 在现有工具中使用所需的文件、CLI 或 MCP 能力，参考对应接入文档配置；同一工具在不同客户端中的配置方式以该客户端为准 |
| 希望常驻运行个人服务 | 按 [快速开始](setup.md) 准备容器、组件和凭据，部署仓库中的主栈 |
| 希望为课题组提供共享入口 | 参考 [团队应用案例](team-use-cases.md) 与 [团队部署](server-deploy.md)，使用自己的机器人身份与服务 |

仓库中的爱玛士、爱码士、道元、天一、知汛等名称来自具体应用配置。迁移时需要相应调整 Agent 身份、应用凭据、账号白名单、知识库和推送目标。

## 4. 验证一条完整任务

1. 让助手读取你指定的一份资料或项目文件，检查来源与访问范围。
2. 调用一个已配置工具，核对实际输出；代码任务记录命令、退出码与日志。
3. 将结果保存到自己的笔记、任务库或仓库，确认位置正确。
4. 从保存的结果继续下一次任务，确认上下文和引用可以找回。

工具连通、任务完成和结论正确要分别核对。只有保存了实际输出，后续简报、提醒和复盘才有可靠依据。

## 5. 再加入专业能力和自动化

| 需求 | 可复用的方法 | 团队中的例子 |
|---|---|---|
| 查询专业资料或业务数据 | 通过 MCP / API / CLI 接入自己的专业服务 | 知汛接入水文 MCP |
| 跟进项目进度 | 读取自己的仓库与任务信息，生成简报 | 天一与仓库统计 |
| 整理知识与会议行动项 | 接入自己的知识库、笔记和事务工具 | 语雀、文献库与 aisecretary |
| 跟进计算环境 | 接入自己的运行日志、监控接口与通知渠道 | 团队服务器监控 |
| 定时整理与通知 | 在任务已验证后配置调度、推送和备份 | [调度系统](scheduling.md)、[备份](backup.md) |

这些接口是扩展新工具的接入方式，不表示任意第三方应用已经有现成适配器。Paper2Code、统一实验调度和自动研究循环的设计见 [科研助手规划](research-platform-roadmap.md) 与 [研究引擎接入](research-engine-integration.md)。

## 使用成本与部署范围

MySciAgent 不收取平台使用费；模型调用、计算资源和第三方账号由使用者自行选择。已有的账号、工具和计算环境可以继续复用，各组件遵循各自的许可证。

完整主栈由 `scripts/start.sh` 启动，包含多个 Agent 和工具服务，并按默认组件清单预检；本文中的“按需接入”指选择自己需要的工具与工作流程，不代表启动脚本已经提供任意服务组合开关。完整启动前请完成 [部署依赖检查](setup.md#component-preflight)。
