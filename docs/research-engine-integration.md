# MySciAgent 研究引擎接入设计

日期：2026-10-15。状态：设计稿，尚未实现或部署。本设计基于 [AI Scientist 调研](ai-scientist-landscape.md)，保留 [科研平台规划](research-platform-roadmap.md) 中的真实应用接入目标。

## 目的和第一条任务

给定一个课题、已有仓库和资料，平台能规划一个可验收的小实验，在独立工作区执行，比较基线，记录证据，并把结果写回已有笔记。自动研究由用户指定范围、预算与停止条件，支持中断与继续。

第一条任务使用已经可运行的研究基线，不要求从零实现模型。优先选择数据已取得、评测可固定、运行费用可控的项目。水文预测是候选场景，实际数据/代码/服务器尚待用户登记。

## 三类研究引擎

| 引擎类型 | 工作 | 接入方式与时机 |
|---|---|---|
| 单次实现/复现 | 论文规格、代码改动、测试与最小实验 | 首版，借鉴 PaperCoder 的分阶段产物，不先引入整个外部系统 |
| 预算内迭代搜索 | 反复提出、执行和评估候选 | 首版小循环借鉴 autoresearch；以后在同一任务上评估 OpenEvolve 或 ShinkaEvolve 中一种 |
| 方法工具化 | 将已验证的科研代码封装为工具与说明 | 复现之后，借鉴 Paper2Agent，注册为以后可复用的方法 |

上述引擎共享课题、运行和产物协议。研究引擎不直接接管个人所有应用凭据；应用能力由统一工具适配层提供。

## 核心对象与交付契约

| 对象 | 关键字段 | 用途 |
|---|---|---|
| ResearchProject | project_id、问题、资源引用、仓库、数据、环境、笔记目标 | 维护当前研究背景 |
| ResearchPlan | plan_id、证据、候选假设、基线、验收、预算、审批状态 | 将高层目标转为可执行方案 |
| MethodSpec | paper_id、页码/章节、公式与模块映射、缺失设定、参考输出 | 管理论文到实现的依据 |
| ExperimentSpec | experiment_id、代码基线、可修改范围、命令、数据划分、种子、评测器、预算 | 定义公平、可重复的比较 |
| RunRecord | run_id、父候选、代码 commit、环境、原始日志、指标、状态、成本、产物摘要 | 记录每次尝试，包括失败 |
| ResearchFinding | finding_id、结论、支持/反驳 Run、局限、状态、回写链接 | 将结论与证据绑定 |

这些对象是建议的新协议。初版可以用普通 JSON/YAML 与现有数据库保存，不先要求知识图谱或向量数据库。大型原始数据和模型另存，只登记位置、版本与校验信息。

## 统一引擎接口

```python
# Proposed contract, not current implementation.
class ResearchEngine:
    def validate(self, spec): ...
    def submit(self, spec) -> str: ...       # 返回 job_id，后台执行
    def status(self, job_id): ...
    def cancel(self, job_id): ...
    def artifacts(self, job_id): ...
```

平台给每个引擎分配运行目录和预算；引擎通过事件报告候选、代码、测试、运行、评分和下一步决策。外部引擎的数据库、日志和候选 ID 由适配器映射到 RunRecord，不把外部路径或私有格式当成平台唯一事实。

## 工作流与状态

```text
课题与已有资料
   → 方案和实验规格
   → 人工确认范围/预算
   → 在独立分支/worktree 实现
   → 自动测试与运行
   → 独立评测
   → 接受 / 拒绝 / 修复 / 升级 / 停止
   → 复验、归档和笔记回写
```

运行状态建议：QUEUED、RUNNING、SUCCEEDED、FAILED、CANCELLED、INTERRUPTED；研究决策另存为 ACCEPT、REJECT、REPAIR、ESCALATE、STOP。运行退出成功并不自动产生 ACCEPT，指标未改善也不等于执行失败。

固定的数据划分和评测器由验证侧掌管，执行 Agent 只改批准的代码/配置范围。隔离应在实际文件权限、进程或容器边界中落实，不能仅靠提示词。每个候选均保存记录；预算结束时保留最优有效候选和完整失败清单。

## 模型与 Agent 调度

| 任务 | 默认职责 | 升级或交接条件 |
|---|---|---|
| 证据整理 | 文献 Agent，提取带来源的方法与事实 | 引用缺失、文献冲突时交规划审查 |
| 研究设计 | 高能力模型制定假设、实验和验收 | 人确认范围后交执行，不把大段聊天当任务规格 |
| 实现与修复 | DeepSeek 等合适的低成本模型，使用结构化计划和工具 | 重复失败、复杂算法或规格冲突时升级；不无限重试 |
| 验证与分析 | 工具计算指标；验证 Agent 核对完整性；关键结论由高能力模型审查 | 原始证据不足则标记未验证，不填造结果 |
| 归档与通知 | 根据已确认结果整理笔记、周报与待办 | 写入操作幂等，保留原应用中的链接和版本 |

模型分工采用可配置路由，根据实测成功率、耗时和费用调整。高能力模型也可承担困难实现，低成本模型也可处理简单规划；不以模型价格代替任务能力判断。

## 接入现有资源

| 现有资源 | 接入角色 | 需验证内容 |
|---|---|---|
| dailyinfo、Zotero/mylibrary、已有 PDF | 论文输入和证据 | 真正使用的数据源、来源引用、去重、全文可读性 |
| GitHub 与本地科研仓库 | 代码与任务产物 | 分支隔离、差异、代码版本、已有改动保护 |
| 本地 Python 或 SSH 服务器 | 实验执行器 | 环境、资源、日志、退出码、超时/取消、断连恢复 |
| 指标文件/已有实验追踪工具 | 独立评测和实验账本 | 指标定义、数据划分、多种子汇总、产物定位 |
| 语雀/实际笔记工具、消息入口 | 知识回写和人工反馈 | 授权、写回能力、幂等、失败重试、对应课题 |

原先 myopenclaw 的多框架部署是可复用基础。最小部署改造需要把与首条科研流程无关的上游硬依赖变为可选，再启动和验证对应服务；当前源码阻塞仍见 [迁移记录](migration-status.md)。

## 五个可执行开发包

1. **定义协议与执行证据。** 给已有基线生成 ExperimentSpec，固定评测器，执行一个真实 Run 并登记原始日志、指标、代码和环境。验收：另一台允许的相同环境能按记录复跑。
2. **实现有限循环。** 单候选实现、运行、评测、决策，配置总预算、候选数和失败次数；支持取消与恢复。验收：能展示改善、无改善和崩溃三种路径，记录均不丢失。
3. **接入高低成本模型交接。** 规划和执行采用同一任务协议，关键审查读取原始证据。验收：一次真实任务经过完整交接，费用/耗时分步骤可查。
4. **实现论文两路复用。** 选择一篇已有代码的论文，先验证并工具化；再选择一个范围明确、需要补实现的方法模块。验收：方法依据、代码、测试、Run 和差异说明可双向定位。
5. **完成日常流程和引擎对照。** 将记录写回实际笔记应用；需要扩大搜索时，只选择一种外部引擎在相同预算下对照简单循环。验收：以真实有效结果、人工接管和总成本评估收益。

## 完成标准

平台应该能够回答：“这个结论来自哪篇论文的哪个设定、哪次代码提交、哪个数据版本、哪些 Run 和哪些指标？”同时应能暂停、恢复和纠正研究。仅有多 Agent 对话、能生成报告或单个成功演示，都不足以证明这个流程已经实现。
